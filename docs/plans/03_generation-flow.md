# 기획서 03 — 생성 플로우 (Runway식)

## 1. 개요

확정된 소재 카드를 골라 설정 칩 몇 개를 고르고 "생성 시작"을 누르면 4단계
진행률로 파이프라인(대본→음성→비주얼→조립)이 돌아가는 화면. 주 사용자:
카드를 맡은 사람(owner).

## 2. 목표·성공 기준

- 생성 시작까지 클릭 3번 이내(카드 선택 → 칩 확인 → 시작).
- 데모 합격 기준: 생성 시작 후 4단계가 순차 진행되고, 완료 시 "편집 화면으로"
  버튼이 나타난다.

## 3. 사용자 시나리오

- B가 자기가 맡은 일본 머니 카드 선택 → 길이 칩 `12분`, 프리셋 `longform_16x9`
  확인 → **생성 시작** → 진행률 보다가 다른 탭으로 이동 → 완료 알림 받고 복귀.
- 드라마썰 카드: 비주얼 단계에서 "수동 대기열 7건" 표시 → B가 MJ에서 생성해
  업로드해야 다음 단계 진행.

## 4. 화면 구성

- 좌: 확정된 소재 카드 목록(내가 맡은 카드 우선 정렬).
- 중: 선택 카드 상세 + **설정 칩** — 길이(10/12/15분·플레이리스트 60분),
  프리셋, 발행 예약 슬롯. 트랙별 기본값은 채널 바이블·트랙 설정에서 프리필.
- 하: **생성 시작** 버튼 → 4단계 진행률 바: `① 대본` `② 목소리` `③ 그림` `④ 조립`
  (단계별 부제: 씬 28개 작성 중… / 씬 12/28 녹음… / 수동 대기열 7건 대기… / 믹스 중…).

## 5. 핵심 인터랙션

- 카드 선택은 owner만 가능 — 다른 카드는 **내가 맡기**부터.
- **생성 시작** → 서버 잡 생성, 버튼은 진행률 뷰로 전환(중복 클릭 방지).
- ③ 그림 단계에서 수동 대기열 잔여 건수 노출 + "대기열 열기" 링크(M2 비주얼 대기열).
- 완료 시 **편집 화면으로** / 실패 시 실패 단계에 재시도 버튼.

## 6. 데이터·API 매핑

- 카드: `CardModel(approved_by NOT NULL)`. 시작: `POST /episodes` → RQ `generate` 잡.
- 진행률: 단계 = statemachine 상태 매핑 (`scripted`=①완료, `voiced`=②완료,
  `rendered`=④완료). 폴링 또는 SSE `GET /episodes/{id}/progress`.
- 길이 칩 → script.py 길이 제어 파라미터(§5-7: 씬 26~32개, 3,300~3,600자).

## 7. 절대 규칙 반영 (§5)

- **5-4**: 소재 확정 안 된 카드는 목록에 아예 안 나옴(게이트 1). owner 아닌
  카드는 생성 시작 불가(클레임 잠금).
- **5-7 길이 제어**: 길이 칩이 씬 수·글자수 목표를 표시. TTS 실측 합산 미달 시
  ② 단계에 "보강 씬 생성 중" 서브 상태.
- **10장**: ③ 그림 단계는 MJ/Higgsfield 자동 호출 없음 — 수동 대기열 카운트만.

## 8. 엣지케이스

- 생성 중 이탈 후 복귀: 진행률 이어서 표시(서버가 소스 오브 트루스).
- ② 단계에서 ElevenLabs 쿼터 80% 초과: 경고 배너 + 계속/중단 선택 (§5-8).
- 동일 카드로 재생성 시도: 기존 에피소드 존재 알림 → 편집 화면 유도.

## 9. 데모 체크리스트

- [ ] 확정된 카드만 목록에 보인다
- [ ] 설정 칩 기본값이 트랙별로 다르다 (플레이리스트=60분)
- [ ] 생성 시작 → 4단계가 순차 진행된다
- [ ] ③ 단계에 수동 대기열 잔여 건수가 보인다
- [ ] 완료 후 "편집 화면으로" 버튼이 나타난다
