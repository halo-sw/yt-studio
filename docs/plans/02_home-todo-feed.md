# 기획서 02 — 홈 할 일 피드 (받은편지함 패턴)

## 1. 개요

접속 시 처음 보는 화면. 5개 채널 전체에서 **내가 지금 처리해야 할 일**만 모아
받은편지함처럼 위에서부터 처리해 내려가는 피드. 주 사용자: 3인 전원, 하루 2~3회.

## 2. 목표·성공 기준

- 사람이 개입해야 하는 두 게이트(**소재 확정**, **최종 검토**)가 절대 피드에서
  누락되지 않는다 — 파이프라인이 사람 때문에 멈추는 시간 최소화.
- 데모 합격 기준: 피드에서 항목 하나를 처리(버튼 클릭)하면 피드에서 사라지고
  카운터가 줄어든다.

## 3. 사용자 시나리오

- A 접속 → 피드 상단 "드라마썰 새 소재 3건 — 확정 필요" → 카드 훑고 2건
  **소재 확정**, 1건 보류 → 다음 항목 "일본 머니 렌더 완료 — 최종 검토" →
  04 편집 화면으로 이동해 검토.
- C 접속 → "함께 결정 1건 — 썸네일 시안 투표" → 투표 후 피드 비움.

## 4. 화면 구성

- 상단: 오늘 요약 스트립 (검토 대기 n / 확정 대기 n / 투표 대기 n / 실패 n).
- 본문: 할 일 카드 세로 피드. 카드 = 채널 태그 + 유형 아이콘 + 제목 + 1줄 맥락 +
  기본 액션 버튼 1개(그 자리에서 처리) 또는 상세로 이동.
- 유형 4종: `소재 확정 요청` `최종 검토 요청` `투표 요청` `실패 알림`.

## 5. 핵심 인터랙션

- `소재 확정 요청` 카드: 본문 미리보기 펼침 → **소재 확정** / **넘기기**.
- `최종 검토 요청` 카드: **검토하러 가기** → 04 편집 화면 딥링크.
- `투표 요청` 카드: **함께 결정으로** → 05 화면 딥링크.
- 처리된 카드는 피드에서 즉시 제거(낙관적 갱신), 실패 시 되돌림 토스트.

## 6. 데이터·API 매핑

- 피드 항목: `CardModel(state=draft, approved_by IS NULL)` → 확정 요청,
  `EpisodeModel(state=rendered)` → 검토 요청, `VoteModel` 미투표 → 투표 요청,
  실패 잡(RQ) → 실패 알림. 통합 `GET /todo` (M2).
- **소재 확정** 버튼 → `statemachine.approve_material` 호출 라우터.

## 7. 절대 규칙 반영 (§5)

- **5-4 셀프 검수 금지**: 내가 owner인 에피소드의 `최종 검토 요청`은 내 피드에
  뜨지 않는다(서버에서 필터). 잘못 진입해도 승인 API가 403.
- **5-8 관제 임계**: 실패 잡(재시도 2회 소진)·ElevenLabs 80% 경고가 `실패/경고`
  카드로 피드 최상단 고정.

## 8. 엣지케이스

- 할 일 0건: "모두 처리했어요" 빈 상태 + 채널별 다음 예약 발행 시각 표시.
- 두 사람이 동시에 같은 카드 처리: 늦은 쪽에 "이미 B가 확정했어요" 토스트.

## 9. 데모 체크리스트

- [ ] 유형 4종 카드가 각각 1개 이상 피드에 보인다
- [ ] 소재 확정 클릭 → 카드 제거 + 상단 카운터 감소
- [ ] 내가 owner인 검토 요청이 피드에 없다 (다른 사용자 시점 전환으로 확인)
- [ ] 실패 알림이 최상단에 고정된다
