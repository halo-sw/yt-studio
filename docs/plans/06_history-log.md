# 기획서 06 — 기록 (감사 로그 + 사용량)

## 1. 개요

"누가 언제 무엇을 했나"(감사 로그)와 "돈이 어디에 얼마나 나가고 있나"(외부 API
사용량)를 보는 화면. 문제가 생겼을 때 되짚는 곳이자 §5-8 관제 임계의 대시보드.
주 사용자: 3인 전원(주 1회 점검), 장애·분쟁 시 수시.

## 2. 목표·성공 기준

- 어떤 에피소드든 draft부터 published까지 전 이력을 1분 안에 추적 가능.
- ElevenLabs 사용량이 80%를 넘으면 이 화면과 홈 피드 양쪽에서 경고가 보인다.
- 데모 합격 기준: 로그를 카드/사람/기간으로 필터할 수 있고, 사용량 게이지에
  80% 경고선이 표시된다.

## 3. 사용자 시나리오

- "이 카드 누가 확정했지?" → 카드 ID 필터 → `소재 확정 (B)` → `scripted 전환 (A)`
  → … → `발행 verify 완료` 타임라인 확인.
- 월말 정산: 사용량 탭 → ElevenLabs 이번 달 크레딧, **재생성으로 쓴 비중** 확인
  → 재생성 과다 트랙을 함께 결정 안건으로 올림.

## 4. 화면 구성

- 탭 2개: **기록**(감사 로그) / **사용량**.
- 기록 탭: 필터 바(카드/에피소드 ID, 사람, 기간, 이벤트 유형) + 시간 역순
  타임라인 리스트(시각 · 사람 · 행위 일상어 표기 · 카드 링크).
- 사용량 탭: 서비스별 게이지(ElevenLabs 크레딧 — 80% 경고선 표시, YouTube 쿼터,
  Anthropic 토큰) + 채널별·**최초 생성 vs 재생성** 분리 막대 + 실패 잡 목록(재시도 이력).

## 5. 핵심 인터랙션

- 로그 행 클릭 → 해당 카드/에피소드로 딥링크.
- 행위 표기는 일상어: "맡음", "소재 확정", "장면 7 다시 만듦", "검토 완료",
  "발행 예약", "발행 확인됨".
- 사용량 게이지 80% 초과 시 적색 + "홈에도 경고를 띄웠어요" 표시.

## 6. 데이터·API 매핑

- 기록: `AuditLogModel` (`GET /logs?card_id=&actor=&from=&to=`).
- 사용량: `UsageLogModel` 집계 — `is_regen` 컬럼으로 최초/재생성 분리 (§5-8),
  `GET /usage?service=&period=`.
- 실패 잡: RQ failed registry + 재시도 카운트.

## 7. 절대 규칙 반영 (§5)

- **4장 감사 원칙**: 모든 상태 전환·클레임·확정·승인·투표 가결이 빠짐없이
  기록 — statemachine이 AuditEntry를 반환하고 라우터가 반드시 저장하므로
  UI는 누락 없음을 전제로 설계.
- **5-8 관제 임계**: 80% 경고선·재생성 크레딧 별도 집계·실패 잡(재시도 2회
  소진) 알림 이력이 이 화면의 1급 시민.
- **5-6**: 발행 이벤트는 "발행 예약"과 "발행 확인됨(verify)"이 별개 로그 행 —
  verify 없는 발행이 눈에 띄게.

## 8. 엣지케이스

- 로그 대량 적재: 기간 기본값 최근 7일, 무한 스크롤.
- 사용량 API 일시 장애: 마지막 수집 시각 표시 + 스테일 배지.
- verify 실패한 발행: 사용량 탭 아닌 기록 탭 최상단에 경고 고정.

## 9. 데모 체크리스트

- [ ] 카드 하나의 전 이력이 타임라인으로 이어진다
- [ ] 행위가 전부 일상어로 표기된다
- [ ] ElevenLabs 게이지에 80% 경고선이 보인다
- [ ] 최초 생성 vs 재생성 크레딧이 분리 표시된다
- [ ] "발행 예약"과 "발행 확인됨"이 별개 행으로 보인다
