# 리캡(냐옹체) 트랙 — 소재발굴→제작→편집→업로드 전자동화 설계

> ⚠ **대체됨**: 이 문서는 검토 이력이다. 운영 기준은 `docs/PLAYBOOK.md` 하나만 따른다.

> 참고 템플릿: 냐옹무비(3.7만, 80편) / 냐옹관(7만, 131편, 일 1.46편, 상위 영상 500만~1,344만 조회)
> 및 유사 채널(걍석주 등). 업로드된 샘플 3종(문체 변환 프롬프트 1 + 상위 영상 자막 덤프 2) 분석 기반.
> **주의: 6번째 트랙 신설은 스코프 확장 — 착수 전 3인 합의 필요 (CLAUDE.md 10장).**

## 0. 템플릿 역해부 — 이 채널들이 실제로 하는 일

- **포맷**: 원본 영상(영화·단편·중국 숏무비)의 스토리를 빠른 템포 내레이션으로 재구성.
  영상 = 원본 푸티지 컷 + 내레이션 + 자막. 편당 8~15분(쇼츠 파생 포함).
- **문체(냐옹체)** — 샘플 프롬프트가 정량 스펙까지 확정해 줌:
  - 연결어 분포: ~했는데 40% / ~했고 25% / ~하자 15% / ~했죠 10% / ~했습니다 5%
  - 같은 연결어 3연속 금지, 연결어마다 행 변경(자막 호흡 단위)
  - 원본 충실성: 관객·시청자 언급 금지, 원본에 없는 창작 금지, 행동 중심·내면묘사 최소화
  - 존댓말 고정, 유머 5~10%, 유튜브 금칙어 치환표(죽었다→세상을 떠났다 등)
- **볼륨 전략**: 일 1~1.5편 꾸준 발행. 소재는 검증된 원본(이미 터진 영화/숏무비)에서 나옴.

이 스펙의 90%는 **코드로 검증 가능한 규칙**이다 — 우리 script.py의 린터 구조(lint_conte,
lint_fact_rule)와 정확히 같은 방식으로 강제할 수 있다. 이게 이 템플릿이 자동화 친화적인 이유.

## 1. 전제: 저작권 — 파이프라인보다 먼저 결정할 것

리캡 포맷의 비주얼은 **원본 푸티지**다. 우리 절대 규칙 5-5(라이선스 메타 없는 클립
ingest 거부)와 정면 충돌하므로, 소재 전략을 먼저 하나 골라야 한다:

| 전략 | 내용 | 리스크 | 비고 |
|---|---|---|---|
| A. 원본 영화 리캡 (냐옹 방식 그대로) | 시중 영화·드라마 푸티지 사용 | Content ID 수익 몰수·차단·경고 누적, 한국 저작권법상 '인용' 요건 불충족 가능 | **우리 규칙 5-5상 ingest 불가.** 채택하려면 규칙 개정+3인 합의 필요, 권장 안 함 |
| B. 라이선스 확보 소재 | CC/퍼블릭도메인 영화, 무료 공개 단편, 제작자 제휴 숏무비 | 낮음 | **권장 시작점.** 냐옹관 상위 영상 다수도 (중국계) 숏무비 — 제휴 여지 있는 카테고리 |
| C. 자체 생성 비주얼 재연 | 스토리는 리캡, 비주얼은 생성 이미지/클립 (드라마썰 트랙과 동일 원칙) | 낮음 (문체·구성만 차용) | 원본 푸티지 흡인력은 포기. 기존 파이프라인 그대로 사용 가능 |

이하 설계는 B 기준 (C는 기존 longform 파이프라인에 문체 트랙만 추가하면 끝이라 별도 설계 불요).

## 2. 파이프라인 설계 — 기존 모듈 재사용 맵

핵심 결론: **4단계 중 3단계는 이미 있는 부품의 조합이고, 진짜 신규는 1개(클립 싱크 조립)뿐이다.**

```
[소재발굴]          [제작]              [편집]               [업로드]
scout.py(있음)  →  recap 트랙(신규·소형) →  breakdown.py(있음)   →  publish.py(M3)
+ source_ingest     nyaong_writer.py      + clip_sync(신규)        하이브리드 예약
  (신규·소형)       + style_lint          + assemble 프리셋
                                            (기존 확장)
        ▲ 사람 게이트 1: 소재 확정                ▲ 사람 게이트 2: 최종 검토
          (+라이선스 확인)
```

### 2-1. 소재발굴 (기존 scout.py 확장 + source_ingest 신규)

- **경쟁 폴링**: scout.py에 리캡 채널군(냐옹관·냐옹무비·걍석주 등) 등록. 기존 아웃라이어
  감지(조회수/구독자 비율·업로드 경과시간)가 "어떤 원본이 터지는가"를 그대로 알려줌.
- **역해부**: 터진 리캡 영상을 breakdown.py로 분해 → 컷 리듬·훅 밀도 스터디 (이미 구현됨).
- **원본 소싱(신규 `core/source_ingest.py`)**:
  1. 후보 원본 등록 (URL + **라이선스 메타 필수** — 없으면 규칙 5-5로 즉시 거부)
  2. yt-dlp로 영상+자막 수집, 자막 없으면 Whisper STT
  3. breakdown.py 샷 감지 → 샷 타임라인 생성
  4. 소재 카드 생성 → **사람 게이트 1: 소재 확정** (라이선스 확인 포함, UI 기존 카드 플로우)

### 2-2. 제작 (tracks/recap/ 신규 — 소형)

- **`nyaong_writer.py`**: 업로드된 샘플 프롬프트를 TRACK_PROMPTS 형식으로 이식.
  입력 = 원본 자막/이벤트 시퀀스, 출력 = 씬 JSON (기존 스키마 그대로.
  씬 = 내레이션 비트 1개, visual.ref = 원본 샷 타임코드 `src#t=12.4-18.2`).
- **`style_lint.py`** — 냐옹체를 코드로 강제 (script.py 린터 패턴 재사용):
  - 연결어 분포 검사 (40/25/15/10/5 ± 허용오차), 3연속 반복 검사
  - 금지 표현 검사: "관객·시청자·사람들" + 금칙어 치환표 자동 적용
  - 존댓말·행 변경 규칙 검사 → 위반 씬만 부분 재생성 (규칙 5-2 흐름 그대로)
- 원본 충실성은 프롬프트 + "이벤트 시퀀스에 없는 고유명사/사건 감지" 린트로 이중 방어.

### 2-3. 편집 (신규 1개: clip_sync + 기존 assemble 확장)

- **`clip_sync`(신규, assemble.py에 preset_recap으로 추가)** — 유일한 진짜 신규 렌더 로직:
  1. 씬별 TTS 실측 duration (기존 tts.py)
  2. visual.ref의 원본 샷 구간을 ffmpeg trim → 내레이션 길이에 맞춰 컷 선택/속도 미세조정
     (샷이 짧으면 인접 샷 이어붙임 — breakdown.py 샷 경계 재사용)
  3. 씬 세그먼트 렌더 = 기존 render_scene_segment 변형 (이미지 대신 클립 입력)
  4. 자막 번인·2트랙 믹스·챕터·씬 교체 전부 기존 코드 그대로
- **쇼츠 파생**: 세그먼트가 씬 단위 파일이므로 훅 씬 2~3개 → 9:16 크롭 프리셋(preset_shorts)
  추가로 본편 1개당 쇼츠 2~3개 자동 파생.

### 2-4. 업로드 (M3 publish.py — 설계 변경 없음)

- 제목 3안(냐옹관 제목 패턴: "~하면 생기는 일", "~해버린 남자" 등 템플릿 학습) + 설명 +
  예약 초안 업로드 → **사람이 공개 전환** (규칙 5-6). verify 필수.
- 발행 후 harvest.py 지표가 scout 가중치로 피드백 → "터지는 원본 유형"이 소재 큐에 반영.

## 3. 자동화 커버리지와 사람의 일

| 단계 | 자동화율 | 사람이 하는 일 |
|---|---|---|
| 소재발굴 | ~90% | 소재 확정 클릭 + 라이선스 확인 (게이트 1) |
| 대본 | ~95% | (린트 통과 실패 씬 검토 정도) |
| 편집 | ~90% | 어색한 씬 "이 장면만 다시 만들기" |
| 업로드 | ~80% | 최종 검토 + 공개 전환 (게이트 2) |

목표 처리량: 편당 사람 개입 20~30분 → 냐옹관 수준(일 1.5편)은 1인 하루 1시간 내.

## 4. 구현 순서 (합의 후 착수 기준, 총 ~1주)

1. `tracks/recap/nyaong_writer.py` + `style_lint.py` — 샘플 프롬프트 이식 + 린터 (1~2일)
2. `core/source_ingest.py` — yt-dlp+Whisper+라이선스 게이트 (1일)
3. `assemble.preset_recap` + `preset_shorts` — clip_sync 조립 (2일)
4. scout 채널군 등록 + e2e 검증: 라이선스 확보 원본 1편 → 완성 리캡 1편 실렌더 (1일)

## 5. 결정 필요 사항 (3인 합의 안건)

1. 트랙 신설 여부 (스코프 확장 — CLAUDE.md 10장)
2. 소재 전략 A/B/C 중 선택 — **권장: B로 시작, A는 금지 유지**
3. 기존 5트랙 중 대체할 트랙이 있는지 vs 6트랙 병렬
