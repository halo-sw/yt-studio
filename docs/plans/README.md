# 화면 기획서 — 작성법과 목차

> channel-factory 대시보드의 화면별 기획서 모음.
> CLAUDE.md §10에 따라 **대시보드 5화면 + 에이전트 레일/워크스페이스** 외
> 신규 화면 기획서는 3인 합의 전 추가하지 않는다.

## 기획서 작성법 (공통 템플릿)

모든 화면 기획서는 아래 9개 섹션을 같은 순서로 작성한다.
새 기획서를 쓸 때 이 절을 복사해서 시작하면 된다.

| # | 섹션 | 반드시 담을 것 |
|---|---|---|
| 1 | 개요 | 화면 한 줄 정의 + 주 사용자(3인 중 누가, 언제) |
| 2 | 목표·성공 기준 | "데모에서 이걸 눌러 이게 보이면 합격" 수준으로 구체화 |
| 3 | 사용자 시나리오 | 실명 대신 A/B/C 역할로, 시작→끝 흐름 2~3개 |
| 4 | 화면 구성 | 영역 분할(레이아웃)을 글로 그린다. 와이어프레임 대체 |
| 5 | 핵심 인터랙션 | 버튼·상태 변화. **용어는 일상어**(내가 맡기, 소재 확정, 이 장면만 다시 만들기, 발행 예약) — claim/regen 같은 개발 용어는 코드 내부에서만 |
| 6 | 데이터·API 매핑 | M0 모델(core/schemas.py, core/models.py) 필드와 M2 라우터(service/api)로 연결 |
| 7 | 절대 규칙 반영 | CLAUDE.md §5 중 이 화면이 강제·노출하는 규칙과 그 방식 |
| 8 | 엣지케이스 | 충돌·권한·빈 상태(empty state) 처리 |
| 9 | 데모 체크리스트 | 데모 시연 시 확인할 체크박스 목록 |

작성 원칙:

- **사양 원본은 `demo/channel_factory_demo.jsx`** — 원본이 도착하면 기획서와
  충돌하는 부분은 원본을 따르고 기획서를 갱신한다. 원본이 없는 동안 이
  기획서들이 데모 제작의 근거다.
- 화면마다 §5 절대 규칙 매핑 섹션이 비어 있으면 리뷰 반려. 규칙이 UI에
  안 보이면 지켜지지 않는다.
- 수치·상태값은 기획서에 하드코딩하지 말고 모델 필드명으로 쓴다
  (예: "Scene.duration 합계", "Card.owner").
