## 0-1. 타겟 카테고리 — 수익 포지셔닝 (확정)

숏폼 스토리 채널의 수익은 두 변수의 곱이다: **바이럴(도달) × RPM(광고단가)**.
스토리물은 바이럴은 높지만 RPM이 낮고, 금융·법률은 RPM이 높지만 바이럴이 낮다.
그래서 **소재를 "고RPM 광고군에 인접한 스토리"로 좁혀** 둘을 동시에 잡는다.

| 순위 | 서브 카테고리 | RPM대(국내) | 바이럴 | 경쟁 | 포지셔닝 |
|---|---|---|---|---|---|
| **1 (주력)** | **금전·사기·상속 사연** (돈 떼인 이야기, 보증, 유산 다툼) | 높음 ★★★ | 높음 | 중 | 금융·보험 광고군 인접 → RPM↑, "돈" 소재는 클릭·공유 모두 강함 |
| **2 (주력)** | **직장·갑질 반전** (부당해고, 공로 가로채기, 내부고발) | 중상 ★★ | 매우 높음 | 중 | 직장인 타겟 = 구매력 높은 시청자, 통쾌 서사로 완주율↑ |
| 3 (성장) | 미스터리·실화풍 반전 (일상 속 비밀) | 중 ★ | 매우 높음 | 상 | 완주율·구독 전환 최고. 성장 엔진, RPM은 보통 |
| 4 (보조) | 부동산·정책 얽힌 사연 (전세사기, 재개발) | 높음 ★★★ | 중 | 하 | 니치·고RPM. 소재 고갈 빠름 → 주 1편 |
| 5 (감동) | 가족·관계 회복 | 낮음 | 높음(공유) | 상 | 공유·구독엔 강하나 RPM 낮음 → 비중 축소 |

**확정 포지셔닝**: 채널 정체성 = "**돈과 사람이 얽힌 반전 사연**". 1·2번을 주력(주간 60%),
3번을 성장 엔진(30%), 4번 보조(10%). 5번은 완충용으로만. 이렇게 하면 스토리물의
바이럴을 유지하면서 광고 단가를 금융·직장 시청자 쪽으로 끌어올린다.
→ 소재 프롬프트(§4-A)의 "5축"은 이 5개 카테고리로 확정한다.

## 1. 두 제작 레인 — 언제 무엇을 쓰나

**레인 ① 생성 (기본값, 발행량의 80%+)**
창작 스토리 → 냐옹체 대본 → 생성/플레이스홀더 비주얼 → 렌더.
저작권 리스크 0. 소재는 무한(모티프 조합). 오늘부터 가능.

**레인 ② 클리핑 (조건 충족 시에만)**
원본 영상 컷싱크 리캡. **라이선스 근거(permission_ref)가 있는 원본만** — CC·퍼블릭도메인·제작자 제휴·자체 촬영분. 조건: 코드가 강제한다. 라이선스 메타 없으면 `ingest_source`가 거부하므로 우회 시도 금지. 시중 영화·드라마·타인 유튜브 영상은 **금지** (Content ID·경고 리스크, 규칙 5-5).

## 2. 일일 루틴 (총 ~30분, 나머지는 자동)

```
① 소재 (5분) — 아래 §4-A 프롬프트로 소재 3개 → 1개 확정
② 대본 (5분) — §4-B 프롬프트 → 출력 전문을 data/scripts/{슬러그}.txt 저장
③ 제작 (0분, 자동)
   python cli.py produce --script data/scripts/{슬러그}.txt --title "제목" --shorts
   → 린트 자동검수(위반 행만 재생성) → TTS → 렌더 → shorts.mp4 + meta.txt
④ 패키징 (5분) — §5 규칙으로 제목·썸네일 확정 (meta.txt 초안 활용)
⑤ 업로드 (5분) — 예약 18:00, 공개 전환은 사람이 (게이트)
⑥ 발행 직후 — 고정 댓글 1개 (질문 or 다음 화 예고)
```

클리핑 레인일 때는 ②③이 원커맨드로 합쳐진다 — **다운로드→클립 컷→대본→TTS→자막 번인→편집→쇼츠**:
```
python cli.py clip \
  --source "URL 또는 로컬파일" --title "제목" \
  --license-source "권리자" --license "CC-BY|제휴계약|자체제작" --permission-ref "근거" \
  --transcript 자막또는사건요약.txt --shorts
```
- `--source`에 URL을 주면 yt-dlp가 다운로드하고, 샷 경계를 자동 감지해 내레이션 길이에 맞춰 컷싱크한다.
- **허가 3종 인자가 없으면 다운로드 전에 멈춘다.** 이건 불편이 아니라 채널 보호 장치다 —
  타인의 유튜브·Douyin·영화 영상을 무단으로 넣는 순간 Content ID·경고로 채널 자산이 날아간다.

### 클리핑 소스 공급처 (허가 게이트를 통과하는 곳)

| 공급처 | 라이선스 | 용도 |
|---|---|---|
| Pexels · Pixabay · Mixkit | 무료 스톡 (상업 가능) | 분위기 컷·B롤 |
| Internet Archive | 퍼블릭 도메인 | 고전 영화 리캡 포맷 |
| 공공누리 1유형 | 출처 표시 | 공공기관 영상 |
| YouTube CC-BY 필터 | 저작자 표시 필수 | 업로더=권리자 검증 후만 |
| **숏무비 제작사 제휴 (핵심)** | 서면 허가 | 메일 1통 = 소스 수백 편. prompts/05 아웃리치 활용 |
| 자체 촬영/생성분 | 자체 제작 | 항상 가능 |

## 3. 대본 규격 (파이프라인 입력 계약)

- **한 행 = 한 절** (연결어 단위 줄바꿈 = 자막 호흡 = 씬 단위)
- 쇼츠: 15~20행 (60~90초) · 롱폼 확장판: 130~150행 (10분)
- 냐옹체 정량 스펙 (produce가 자동 검사):
  - 존댓말 고정 · 연결어 분포 ~했는데 40% / ~했고 25% / ~하자 15% / ~했죠 10% / ~했습니다 5%
  - 같은 연결어 3연속 금지 · "관객/시청자" 언급 금지 · 내면 묘사 최소화
  - 민감 표현은 자동 치환됨 (죽었다→세상을 떠났다 등) — 걱정 말고 스토리에 집중
- 마지막 행: 시그니처 질문 ("여러분이라면 ~했을까요?") — 채널 통일성의 핵심

## 4. 프롬프트 (이 2개만 쓴다 — Claude에 그대로 붙여넣기)

### A. 소재 (아침 5분)

```
너는 스토리텔링 쇼츠 채널의 기획자다. 아래 5축 중 {오늘의 축}에서
창작 스토리 소재 3개를 만들어라. 실존 영화·드라마·실화 재현 금지.

축(수익 포지셔닝 순 — §0-1 확정): ①금전·사기·상속 ②직장·갑질 반전 ③미스터리 반전
④부동산·정책 사연 ⑤가족·관계 회복

각 소재마다:
- 로그라인 1줄 (첫 문장부터 궁금하게 — §4-1 훅 기준 2개 이상 충족)
- 반전 1줄 (후반 70% 지점에 터질 것)
- 마지막 질문 1줄 (댓글 유도)
- 소재의 광고 인접군 1줄 (예: 금전 사연 → 보험·대출 시청자 = 고RPM)
```

### B. 대본 (소재 확정 후 5분)

```
너는 스토리텔링 쇼츠 채널의 작가다. 아래 소재로 60~90초 대본을 써라.

[소재] {로그라인 / 반전 / 마지막 질문}

규칙:
- 한 행 = 한 절. 연결어(~했는데/~했고/~하자/~했죠/~했습니다)마다 행을 바꾼다.
- 15~20행. 존댓말 고정. 행동 중심 서술, 내면 묘사 금지.
- 연결어 분포: 했는데 40% / 했고 25% / 하자 15% / 했죠 10% / 했습니다 5%.
  같은 연결어 3연속 금지.
- "관객/시청자/보는 사람들" 언급 절대 금지.
- 첫 행 = 가장 강한 문장 (10초 시청 약속). 마지막 행 = 소재의 질문.
- 죽었다→세상을 떠났다, 살해→제거, 시체→쓰러진 사람으로 표현.
- 대본 텍스트만 출력 (번호·해설 없이).
```

## 4-1. 훅 검증 체크리스트 (대본 확정 전 필수)

첫 행에서 이탈하면 나머지는 안 본다. 대본 첫 행이 아래 중 **최소 2개**를 만족해야 통과:

- [ ] **구체 수치·시간**: "30년 동안", "매주 화요일", "20년 개근" — 추상어보다 강함
- [ ] **모순·미스터리**: "박스는 늘 텅 비어 있었는데", "불이 저절로 켜졌는데"
- [ ] **인물+갈등 즉시 제시**: "행패를 부리는 할아버지", "첫 번째 해고 대상"
- [ ] **설명이 아닌 장면 한복판에서 시작** (배경 설명 금지)
- [ ] 첫 행에 이미 "끝까지 볼 이유"(질문/약속)가 있는가

첫 배치 5편 검증 결과(전부 통과): 지하실 30년(수치+미스터리) · 빵집 밤12시(시간+미스터리)
· 20년 개근 첫 해고(수치+모순) · 빈 박스 3년(모순+수치) · 우유 행패 할아버지(인물+갈등).

## 4-2. 샘플 먼저, 제휴는 나중 — 검증 우선 전략 (확정)

**순서가 맞다**: 제휴 메일보다 **샘플 업로드 → 반응 검증**이 먼저다. 이유:
- 제휴 메일에 붙일 "실제 성과 지표"가 있어야 제작사가 움직인다 (조회수 = 협상력)
- 반응 데이터로 어떤 카테고리·훅이 먹히는지 먼저 학습 → 헛발 제휴 방지
- **샘플은 생성 레인으로 만든다 — 남의 영상 0개, 저작권 리스크 0.** 그래서 지금 즉시 가능.

주차별:
- **1~2주**: 생성 레인으로 카테고리 1·2·3 각 3~4편씩 쇼츠 업로드 (총 10편+)
- **2주 말**: 24h/48h/7d 지표로 상위 훅·카테고리 식별
- **3주~**: 성과 상위작을 근거로 숏무비 제작사 제휴 아웃리치(prompts/05) → 클리핑 레인 가동

## 4-3. 유튜브 자동화 — 어디까지 되나 (정직하게)

| 단계 | 자동화 | 방법 |
|---|---|---|
| 업로드 | **가능** | YouTube Data API `videos.insert` — 제목·설명·태그·썸네일·예약시간(publishAt) 자동 |
| 예약 발행 | **가능** | privacyStatus=private + publishAt로 예약. 단 규칙 5-6: 최종 공개 전환은 사람 |
| 반응 수집 | **가능** | Analytics API로 24h/48h/7d 조회·완주율·구독전환 폴링 → 상위 소재 자동 랭킹 |
| "떡상 여부" 자동 판정 | 부분 | 공식 지표는 없음. 조회수 속도(velocity)로 추정 — harvest가 임계 초과 시 알림 |

- **제약**: `videos.insert` 쿼터가 크다(기본 일 ~6편) → 대량이면 쿼터 증설 신청. 미인증 앱은
  공개 업로드 제한 → 그래서 "초안 업로드 + 사람 공개" 하이브리드가 설계에 이미 반영됨.
- **구현 위치**: `core/publish.py`(업로드·예약) + `core/harvest.py`(지표 폴링·랭킹). 현재 스텁 →
  OAuth 클라이언트(YOUTUBE_OAUTH_*)만 발급되면 바로 구현 착수 가능. **다음 빌드 1순위.**

## 5. 패키징 규칙

- **제목**: 3전략 중 택1 — 결과 궁금형("~하면 생기는 일") / 반전 암시형("~의 비밀") /
  숫자·시간형("30년간 ~"). 낚시 금지선: 대본에 없는 것을 약속하지 않는다.
- **썸네일 문구**: 6자 이내 대문구 + 12자 보조. 제목과 같은 문장 금지.
- **설명란**: meta.txt의 챕터 붙이고 첫 줄에 검색 키워드 문장. 3번째 줄 = 제휴 링크 슬롯.
- **예약 시간**: 쇼츠 18:00 고정 (4주 후 지표로 보정).

## 6. 주간 지표 루틴 (토요일 15분)

1. 이번 주 쇼츠 7편의 7일 조회수를 5축별로 합산
2. **상위 2축에 다음 주 물량 60% 배분, 최하위 축은 새 축으로 교체**
3. 주간 1등 쇼츠 → 일요일 롱폼 확장판(§4-B를 130~150행 스펙으로) 제작
4. 같은 스토리 훅만 바꾼 재업로드 금지 (중복 판정 리스크)

## 8. 금지선 (요약 — 코드가 대부분 강제)

1. 라이선스 근거 없는 원본 클립 사용 금지 (ingest가 거부)
