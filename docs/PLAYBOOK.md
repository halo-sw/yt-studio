## 1. 제작 레인 2종

**레인 ① 생성 (기본값 — 발행량 80%+)**: 창작 스토리 + 생성 비주얼. 소스 영상 불필요, 저작권 0.
**레인 ② 클리핑 (허가 소스 확보 시)**: 원본 다운로드→샷 감지→컷싱크. 허가 3종 인자 필수(코드 강제).

```bash
# 레인 ① — 대본 파일 하나로 본편+쇼츠+메타까지
python cli.py produce --script data/scripts/파일.txt --title "제목" --shorts

# 레인 ② — URL/파일 → 다운로드 → 클립 → 자막·TTS → 편집 → 쇼츠
python cli.py clip --source "URL" --title "제목" \
  --license-source "권리자" --license "CC-BY|제휴계약|자체제작" --permission-ref "근거" \
  --transcript 자막.txt --shorts
```

클리핑 소스 공급처: Pexels·Pixabay(스톡) / Internet Archive(퍼블릭도메인) / 공공누리 1유형 /
YouTube CC-BY(권리자 검증 후) / **숏무비 제작사 제휴(핵심 — D+60 아웃리치)** / 자체 촬영·생성분.

## 2. 완전한 1편 제작 워크스루 (실례 — 이대로 따라 하면 됨)

**예: 미스터리 카테고리, 월요일 아침**

```
[08:00] ① 소재 (5분)
  §5-A 프롬프트에 "카테고리: 미스터리 반전" 넣고 실행 → 소재 3개 수신
  → "30년 잠긴 지하실" 선택 (훅 체크: 수치○ 미스터리○ → 통과)

[08:05] ② 대본 (5분)
  §5-B 프롬프트에 소재 카드 붙여넣기 → 출력 전문을
  data/scripts/basement.txt 로 저장 (한 행 = 한 절 확인)

[08:10] ③ 제작 (자동 ~3분)
  $ python cli.py produce --script data/scripts/basement.txt \
      --title "30년간 지하실 문을 지킨 경비원의 비밀" --shorts
  → 린트 자동검수 (위반 행 있으면 그 행만 §5-B로 재생성 후 재실행)
  → 산출: data/assets/produce/basement/
     ├ episode.mp4   (16:9 본편)
     ├ shorts.mp4    (9:16 쇼츠 — 이게 오늘 업로드분)
     └ meta.txt      (제목·챕터·설명 초안)

[08:15] ④ 패키징 (5분)
  제목 확정: §6 공식 3개 중 택1 (예: 숫자형 "30년간 ~의 비밀")
  썸네일: §6 규격 (대문구 "30년 봉인" + 보조 "열어보니...")

[08:20] ⑤ 업로드 (5분)
  Studio → shorts.mp4 → 제목/설명(meta.txt 붙여넣기+해시태그)
  → 예약 18:00 KST → 저장
  ※ publish.py 구현 후엔 이 단계도 자동 (OAuth 발급 대기)

[18:05] ⑥ 발행 직후 (2분)
  고정 댓글 1개: "여러분이라면 이 문을 열어봤을까요?" (대본 마지막 질문 재사용)
  지표 시트에 행 추가 (§7 양식)
```

**편당 사람 시간 합계: ~20분.** 이 사이클을 매일 1회.

## 4. 대본 규격 + 품질 게이트

**규격 (파이프라인 입력 계약)**
- 한 행 = 한 절 (연결어 단위 줄바꿈 = 자막 호흡 = 씬)
- 쇼츠 15~20행(60~90초) · 롱폼 확장판 130~150행(10분)
- 마지막 행 = 시그니처 질문 ("여러분이라면 ~했을까요?")

**자동 게이트 (produce가 강제 — 신경 쓸 필요 없음)**
- 연결어 분포 ~했는데40/했고25/하자15/했죠10/했습니다5 (±허용범위) · 3연속 금지
- 존댓말 · "관객/시청자" 언급 금지 · 민감표현 자동 치환(죽었다→세상을 떠났다 등)

**사람 게이트: 훅 체크 (첫 행이 아래 중 2개 이상 — 미달이면 소재부터 다시)**
- [ ] 구체 수치·시간 ("30년", "매주 화요일")
- [ ] 모순·미스터리 ("박스는 늘 텅 비어 있었는데")
- [ ] 인물+갈등 즉시 제시 ("행패 부리는 할아버지")
- [ ] 설명이 아닌 장면 한복판 시작

## 5. 프롬프트 2종 (이것만 쓴다)

### A. 소재 (아침용)

```
너는 스토리텔링 쇼츠 채널의 기획자다. 채널 정체성은 "돈과 사람이 얽힌 반전 사연"이다.
카테고리 {①금전·사기·상속 / ②직장·갑질 반전 / ③미스터리 반전 / ④부동산·정책 사연
/ ⑤가족·관계 회복} 중 {오늘의 카테고리}에서 창작 소재 3개를 만들어라.
실존 영화·드라마·실화 재현 금지.

각 소재마다:
- 로그라인 1줄 — 첫 문장에 구체 수치/시간 + 모순 중 2개 이상
- 반전 1줄 (후반 70% 지점)
- 마지막 질문 1줄 (댓글 유도)
- 광고 인접군 1줄 (예: 상속 분쟁 → 법률·보험 시청자)
```

### B. 대본 (소재 확정 후)

```
너는 스토리텔링 쇼츠 채널의 작가다. 아래 소재로 60~90초 대본을 써라.

[소재] {로그라인 / 반전 / 마지막 질문}

규칙:
- 한 행 = 한 절. 연결어(~했는데/~했고/~하자/~했죠/~했습니다)마다 행을 바꾼다.
- 15~20행. 존댓말 고정. 행동 중심, 내면 묘사 금지. 시간 흐름은 "다음날/그날 밤/잠시 후".
- 연결어 분포: 했는데 40% / 했고 25% / 하자 15% / 했죠 10% / 했습니다 5%. 3연속 금지.
- "관객/시청자/보는 사람들" 언급 절대 금지.
- 첫 행 = 가장 강한 문장. 마지막 행 = 소재의 질문.
- 죽었다→세상을 떠났다, 살해→제거, 시체→쓰러진 사람.
- 대본 텍스트만 출력.
```

(롱폼 확장판: 같은 프롬프트에 "130~150행, 10분. 4/7분 지점 직전 행은 클리프행어" 추가)

## 6. 패키징 공식 (실례 포함)

**제목 3공식 — 대본에 없는 것을 약속하지 않는다**

| 공식 | 형태 | 실례 (첫 배치) |
|---|---|---|
| 숫자형 | "N년간 ~한 이유/비밀" | "30년간 지하실 문을 지킨 경비원의 비밀" |
| 모순형 | "~인데 ~한 사연" | "20년 무결근 직원이 가장 먼저 해고된 이유" |
| 결과형 | "~하면 생기는 일 / ~해버린 결과" | "3년간 빈 박스를 배달하면 생기는 일" |

**썸네일**: 대문구 6자 이내(예: "30년 봉인") + 보조 12자(예: "문을 열자 전부 침묵").
제목과 같은 문장 금지 — 제목이 남긴 궁금증을 증폭.
**설명란**: 1줄 키워드 문장 → meta.txt 챕터 → 3줄째 제휴 링크 슬롯 → `#쇼츠 #사연 #반전`
**고정 댓글**: 대본 마지막 질문 재사용 (초기 댓글 밀도 = 노출 기여)

## 7. 지표 루틴 — 기록 양식과 판단 규칙

**편당 기록 (발행 익일 + 7일차, 시트 한 줄)**

```
날짜 | 파일명 | 카테고리 | 24h 조회 | 7d 조회 | 완주율% | 구독전환 | 훅유형(수치/모순/인물)
```

**판단 규칙 (토요일 15분)**
1. 7d 조회 기준 카테고리 랭킹 → **상위 2개에 다음 주 물량 60%**, 최하위 카테고리는 신규로 교체
2. 완주율 70%↑ 편 → 일요일 롱폼 확장판(130~150행) 제작 대상
3. 완주율 40%↓ 편 → 훅 유형을 기록해 §4 체크리스트에 반례로 추가
4. 조회 속도 이상 감지(발행 6h 내 평소 3배↑) → 해당 카테고리 소재 즉시 2편 추가 생산

※ harvest.py 구현 후엔 1·4가 자동 알림으로 대체된다.
