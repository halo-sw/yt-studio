> **단일 운영 문서.** 프로젝트 전략안(5트랙 병렬, 2026.07.20 수합본)과 구축 완료된
> 자동화 파이프라인(channel-factory 레포)을 통합했다. 이 문서 외의 기획 문서는 폐기됐다.

# PART 1. 전략 (확정)

## 1-1. 결론 요약

- 활성 13개 채널 → **5개 병렬 트랙 + 숏폼 스토리 선봉 채널 + 휴면 8개**. 전 트랙 최소 10분 롱폼(플레이리스트 60분)
- 과거 실패 원인은 자동화가 아니라 **타인 소재 저작권**(레거시 경고 6건+ 전부) → **오리지널 소재 100% 원칙**. 파이프라인이 코드로 강제한다(라이선스 게이트·비평 비중 린터·민감 표현 치환)
- 운영: 3인 공동(역할 없음), 규칙 4개 — 맡기 잠금 · 셀프 검수 금지 · 큰 결정 2/3 합의 · 모든 행동 기록
- 사람 개입은 2곳뿐: **소재 확정**, **최종 검토**. 나머지는 프롬프트+파이프라인+배치 루틴
- 수익 목표: 월 고정비 약 60만 원의 **3배(월 180만 원+)** — 편당 1~2만 뷰의 평범한 성공 × 자동화 편수로 달성

## 1-2. 트랙 확정안 (5 + 선봉 1)

| 트랙 | 채널 | 포맷 | 페르소나/시그니처 | 주 업로드 |
|---|---|---|---|---|
| 일본 시니어 머니 | 신규 「シニアのお金」 | 10~20분, 슬라이드+금액 차트 | 은행 OB '소장'(일본어 이식) | 2편 → 3편 |
| 부동산 | 신규 「예린이의 부동산 뽀개기」 | 10분+(공고 완결), 원문 하이라이트·줌 | 예린 — "청약은 아는 만큼 붙어요" | 1~2편(공고 연동) |
| 드라마썰 | 신규 「톡톡 드라마썰」 | 10~15분, MJ 재연 일러스트+비평 | 톡톡 패밀리 보이스 | 2편 → 3편 + 쇼츠 |
| 사연 | 톡톡 네이트판(유지) | 10~12분, 단일/옴니버스 | 기존 보이스(인지 자산) | 기존 리듬 |

| **숏폼 스토리 (선봉)** | 기확보 채널(구독 1,000+) 피봇 | 60~90초 쇼츠, 냐옹체 창작 스토리 | "돈과 사람이 얽힌 반전 사연" | 매일 1편 |

- 숏폼 선봉의 역할: **가장 빠른 실발행 트랙** — 파이프라인 검증·소재 데이터 수집·쇼츠 수익화
  요건(1,000만뷰/90일) 선점. 발행 재고 10편 완비(§5-2). 검증된 소재는 사연·드라마썰 롱폼으로 승격
- 채널 개설 원칙: 자산은 구독자 수가 아니라 **시청자 데이터의 방향** — 플레이리스트·숏폼 선봉만 재활용, 나머지 신규. 라이선스 없는 클립은 어떤 계정에서도 금지

## 1-3. 일본 니치 근거

일본 금융·투자계 RPM 500~800엔(일반 100~200엔의 3~8배), CPM 1,500~3,000엔+.
시니어×금융 = 최고 단가 + 롱폼 완주율. 11~12월 성수기(단가 1.5~2배) 이전 안착 목표.
건강 잡학은 2호 채널 대기, 보유 시사 완성 대본("현금" 편)은 에피소드로 흡수.
※ 외부 교차 검증(2026): 금융 니치 RPM 최상위($10~25), 서사·실화 $6~13, 엔터 $2~5 — 격차 ~10배.

## 1-4. 비용·수익 설계 (3배)

- 월 고정비 약 55~65만(툴 31만 + 3인 좌석 8~14만 + 감수 2인 12만). 초기 1회성 10만
- 목표 역산(RPM: 일본 5,000 / 부동산 3,500 / 썰·사연 2,000 / 플리 1,000원):
  **월 합계 약 69만 뷰 = 약 185만 원(3.1배)** — 일본 16만·드라마썰 25만·네이트판 15만·부동산 3만·플리 10만 뷰
- 레버 4: ①볼륨(한계비용≈0, 주2→3편) ②단가(미드롤 3~4개+성수기 — **롱폼은 반드시 8분+**)
  ③재배분(90일 KPI 컷→상위 트랙 집중; 일본 단독 36만 뷰로도 3배) ④비광고(로열티·부동산 제휴)
- 도달: 기준 M10~12(성수기 결합 M10) / 낙관 M7~8 / **다운시프트**: M9 수익 < 고정비 1.5배
  → 비용 35만으로 축소해 3배 기준선을 105만으로 방어
- 수익 KPI: M6 100% → M9 200% → M12 300%(달성 시 일본 2호 복제)
- Q4(10~12월) CPM 40~60%↑ → 증설·재고 소진 시즌 / 1~2월 = 실험 시즌

## 1-5. 절대 규칙 (전 트랙 공통 — 파이프라인이 강제)

1. **오디오 2트랙** — 내레이션(-14 LUFS, 씬 단위) / BGM(-26 LUFS, 에피소드 글로벌, 최종 믹스) → 씬 교체에도 음악 연속
2. **부분 재생성은 씬 단위만** — 바이블 잠금 자산 + prev_tail/next_head 주입, 경계 50~100ms 크로스페이드
3. **수치는 사실 시트 단일 출처** — {{fact:키}} 참조만, 파생 차트는 버전 해시 바인딩. 출처는 `data/scripts/SOURCES.md` 대장 기록·분기 갱신
4. **셀프 검수 금지** — 소재 확정자는 그 영상의 최종 승인 불가 (statemachine이 403)
5. **저작권** — 드라마썰: 줄거리 30% 상한+씬당 해석 의무, 배우 유사성·스틸 금지, 비하인드 공개 출처만 / 사연·숏폼: 복수 모티프 결합 재창작 / 클립: 라이선스 메타(permission_ref) 없으면 ingest 거부
6. **발행** — 예약 초안 업로드 → 사람이 공개 전환(하이브리드), 업로드 후 상태 verify
7. **길이 공학** — 10분 = 3,300~3,600자 = 씬 26~32개. 훅 40초 내, 미드롤(4/7/10분) 직전 클리프행어, 마지막 챕터 댓글 유도. 쇼츠는 15~20행(60~90초)
8. **관제** — TTS 사용량 80% 경고, 재생성 크레딧 별도 집계, 합성 콘텐츠 공개 체크 정직하게

**하지 않는 것(학습자료 검증에서 명시 기각)**: 무단 푸티지 리캡·탐지 회피 편집(미러링·색보정)·
출처 미표기·제재 회피 다계정·백색소음 피봇(실측 RPM $3~7·재사용 정책 리스크).
창작(역추적 불가)이 같은 게임의 합법적 최강 수비다.

# PART 2. 마스터 프롬프트 (전 트랙 공용 시스템 프롬프트)

> 대본 생성 시스템 프롬프트 최상단에 고정. 트랙별 블록(PART 3)을 아래 이어붙인다.
> 코드 경로: `core/script.py`가 이 규칙을 프롬프트로 조립하며, 출력은 씬 JSON 스키마(`core/schemas.py`)로 검증된다.

```
당신은 유튜브 롱폼 대본 작가다. 아래 규칙은 예외 없이 지킨다.
[출력 형식]
- 출력은 씬 JSON 배열만. 설명·인사말 금지.
- 씬 스키마: {scene_id, chapter, narration, caption, visual:{type, ref, effect}, duration:null}
- visual.type ∈ slide | chart | doc_highlight | illust | loop_art
- narration은 TTS로 그대로 읽힌다. 괄호 지시문·이모지·특수기호 금지.
[길이 공학]
- 목표 길이 {TARGET_MIN}분 = 내레이션 총 {TARGET_MIN × 350}자(±10%) = 씬 {TARGET_MIN × 2.8~3.2}개.
- 씬당 내레이션 60~90자(18~25초 분량). 한 씬 = 한 메시지.
[리텐션 구조 — 구조적으로 강제]
- 씬 1~2(40초 내): 자기소개보다 먼저, 결과·손익·충격 포인트를 제시하는 훅.
- 4분·7분·10분 지점 직전 씬: 다음 내용 예고형 클리프행어 문장으로 종료.
- 마지막 챕터: 다음 편 예고 + 시청자에게 던지는 질문 1개(댓글 유도) 고정.
[사실·수치 규칙]
- 모든 수치·날짜·고유 조건은 제공된 [사실시트]의 키만 참조한다: 형식 {fact:키이름}.
- 사실시트에 없는 수치는 창작하지 않는다. 필요한데 없으면 needs_fact 목록으로 요청한다.
[오리지널리티 3요소 — 매 편 필수 포함]
① 고유 계산/비교(제공 데이터로 직접 산출한 표·차트 1개 이상)
② 고유 관점(통념에 대한 반박 또는 재해석 1개 이상)
③ 고유 사례 구성(추상 설명을 구체 인물 시나리오로 변환 — 실존 인물 아님을 명시적 가공)
[금지 — 레드펜]
- 투자·의료·법률의 단정("~하면 무조건", "~가 정답") 및 권유("사세요"→"확인해보세요"로)
- 원문(공고·기사·사연·대사) 문장 인용. 사실관계만 재구성.
- 혐오·비하·특정인 평판 언급, 검증 불가한 소문.
- 과장 어그로("충격", "경악")를 사실 근거 없이 사용.
[출력 후 자가 점검]
scenes 마지막에 self_check 객체 첨부: {길이합산자수, 훅_40초내:bool, 클리프행어_지점:[], 오리지널리티3요소:[씬번호], 금지위반:0}
```

# PART 3. 트랙별 프롬프트 블록

조립 순서: 「마스터 프롬프트 + 트랙 블록 + 채널 바이블 요약(data/bibles/{트랙}.yaml) + 사실시트 + (선택)아웃라이어 제목」

## 3-1. 일본 시니어 머니 (persona_jp)

```
[페르소나] 당신은 은행에서 32년 근무하고 퇴직한 '소장'이다. 60대 시청자에게 존댓말로,
어려운 용어는 반드시 생활 비유로 바꿔 설명한다. 1인칭: 私(わたくし).
[언어] 대본은 일본어. 한자어는 시니어 가독 기준(후리가나 필요 어휘 최소화).
[구성 고정 — 12분 표준] 훅(손익 질문) → 소장 인사 → 제도 기본 → 케이스 계산 A/B(chart 필수 2개)
→ 함정·반전 → 체크리스트(3~5개) → 아웃트로.
[내러티브 프레임 로테이션] 손익분기형 / 오해교정형 / 개정대응형 / 세대비교형 / 사례재구성형 / 체크리스트형
중 지난 5편과 다른 프레임 선택, frame 필드에 명시.
[YMYL 강화] 제도 설명만. 개인 상황 단정 금지 — "人によって異なります" 계열 완충 문장을 함정 챕터에 1회 이상.
[출력 추가] 감수자용 노트: 번역 확신도가 낮은 문장 목록(review_flags).
```
- 감수: 대본 단계 1회, 2인 풀 로테이션. 시즌 큐: 연금 개정·확정신고·상속 캘린더 우선

## 3-2. 부동산 「예린이의 부동산 뽀개기」

```
[페르소나] 예린 — 20대, 공고문을 대신 읽어주는 똑똑한 언니. 해요체.
[말투 규칙 5] ① 오프닝은 시청자를 붙잡는 한 마디("잠깐, 스크롤 멈춰요")
② 자문자답 리듬("어디에 몇 세대냐? 원문 그대로 읽어요—")
③ 반전 앞 신호어("근데 여기서 다들 놓치는 거 하나")
④ 숫자 뒤 체감 번역 1줄("월 40만 원씩 굳는 거예요")
⑤ 클로징 시그니처 고정: "청약은 아는 만큼 붙어요 — 예린이었습니다!"
[금지어] 애교체·과한 유행어·"무조건 되세요" 류 단정. '똑똑함'을 깎는 표현 전부.
[구성 고정 — 9챕터 뽀개기] 훅 → 예린 인사 → 공고 개요 → 자격요건 6항목×4비트(항목 소개→원문 하이라이트→해석→해당 여부 체크)
→ 일정 → 비용 계산 → 함정 조항 → 신청 방법 → 아웃트로.
[핵심 준수] visual은 doc_highlight 중심 — ref에 "공고 p{페이지}: {조항명}" 형식으로 원문 위치 지정.
요약 카드로 원문을 대체하지 않는다. 예린 등장(illust)은 인사·전환·아웃트로만.
[사실] 임대료·소득기준·일정은 전부 {fact:} 참조. 파서 미확정 시 needs_fact.
```

## 3-3. 톡톡 드라마썰 (비평·해석형) + 사연 겸용

```
[포지션] 줄거리 전달자가 아니라 비평가. 시청자가 이미 본 작품을 '다시 생각하게' 만든다.
[비평 비중 규칙 — 구조 강제] 전체 내레이션 중 줄거리 서술 30% 이하. 각 씬에 해석·분석 문장 1개 이상 의무.
[구성 고정] 콜드오픈(논쟁 질문: "이 결말, 납득되셨나요?") → 최소 맥락+스포일러 고지 →
핵심 장면 3~4개 해석(요약 짧게·연출 분석 길게) → 반전 분석(왜 작동/실패했나) →
결말 해석+대안 시나리오(오리지널 관점 핵심) → 공개 비하인드(출처 필수) → CTA("여러분의 해석은?").
[재연 컷 규칙] visual.type=illust. ref에는 장면 '분위기·구도' 서술만 — 배우명·작품 스틸 참조 금지,
인물은 [인물카드]의 재창작 외형으로 지정(에피소드 내 고정).
```
